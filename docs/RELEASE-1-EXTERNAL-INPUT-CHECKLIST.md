# Release 1 External-Input Checklist

This checklist identifies evidence that repository code cannot invent. Empty fields are intentional until the named owner supplies the material.

## Examination owner / rules owner

- [ ] Examination identity and organizer/jurisdiction.
- [ ] Exact cycle code and effective date.
- [ ] Subject code and paper/section scope.
- [ ] Official bulletin URL or controlled document artifact.
- [ ] Retrieval timestamp and SHA-256 checksum of the received document.
- [ ] Language/medium policy and permitted translations.
- [ ] Delivery mode, timing, navigation, paper/session boundaries and attempt ceilings.
- [ ] Positive, negative, unattempted and multiple-answer scoring rules.
- [ ] Corrigenda or superseding notices, with precedence order.
- [ ] Named reviewer, role, decision date and approval reference.
- [ ] Regression evidence covering the exact blueprint and scoring rules.

## Academic SME / content owner

- [ ] Syllabus version and Paper I/Paper II unit/topic mapping.
- [ ] Question-version inventory with unique IDs and section assignments.
- [ ] Approved answer-key version for every item.
- [ ] Explanation review status and language review status.
- [ ] Group/comprehension/data-interpretation membership and sequence.
- [ ] Challenge decisions and unresolved-content exclusions.
- [ ] Publication manifest and content fingerprint.
- [ ] Independent reviewer identity for author, review, approval and publication separation.

## Licensing owner

- [ ] Rights status for every selected question and asset: owned, licensed or permitted.
- [ ] Licence/reference ID, holder, permitted audience and territory.
- [ ] Expiry, attribution and redistribution restrictions.
- [ ] Source-copy restrictions for previous-year questions and official documents.
- [ ] Written clearance for any translation, adaptation, image, table or formula asset.

## Security/privacy/accessibility owner

- [ ] Staging secret inventory and rotation owner.
- [ ] Email provider, sender identity, bounce handling and test mailbox policy.
- [ ] TLS certificate/origin policy and `NODE_TLS_REJECT_UNAUTHORIZED` absence check.
- [ ] Data retention, deletion, export and candidate-support procedures.
- [ ] Accessibility acceptance scope, assistive-technology matrix and unresolved issues.

## Approval rule

Synthetic fixtures may be used only in isolated automated tests. They do not satisfy any external approval checkbox and must never be labelled official, licensed, verified or publication-ready.
