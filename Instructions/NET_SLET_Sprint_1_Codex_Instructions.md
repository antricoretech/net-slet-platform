## Sprint 1 objective and boundaries

Deliver a secure, testable foundation for **identity/authorization**, **exam catalogue**, and **versioned exam patterns**. Avoid implementing the full CBT runner, payments, AI tutor, invented question banks, unofficial exam certifications, or mass autogenerated subject data in this sprint.

Work in **small independently testable increments**, respecting existing user modifications. For each increment, state files to change, acceptance criteria, risk/tradeoffs, tests, and final outcome.

### Increment 1A — Architectural ADRs and identity foundation

- Draft `docs/decisions/ADR-0002-authentication.md`: login mechanism, credentials/session storage, email verification approach, CSRF/XSS protections, rate limits, session expiry/revocation, password reset, audit events, environment secrets and production deployment implications. Explain the chosen auth library versus alternatives and do not require paid hosted services by default.
- Create Prisma models/migrations for account and role boundaries (`STUDENT`, `SME`, `ADMIN`), with least privilege; support future roles without hardcoding privileged access into the frontend.
- Implement secure registration/login/logout/session-me API contract with request validation, safe error responses, throttling, and role guards; ensure no public route can self-register as admin/SME. Avoid hardcoded admin accounts and demo passwords in production.
- Build minimal accessible sign-in, registration and student account views in Next.js using the existing styling conventions. No mock authentication presented as real.
- Add API and UI tests for invalid credentials, duplicate email, unverified accounts where applicable, session expiration, authorization bypass, IDOR and successful student onboarding.
- If external email delivery is not configured, leave verification in an explicitly labeled local-development-only pathway and document production requirements.

### Increment 1B — Examination and jurisdiction catalogue

- Draft `docs/decisions/ADR-0003-exam-pattern-lifecycle.md` covering immutable published versions, exam cycle rules and reviewer signoff.
- Extend the existing `Examination`, `ExamCycle`, and `ExamPatternVersion` schema with normalized exam family, official organizer, jurisdiction mapping and lifecycle metadata as needed; use migrations, not direct database edits.
- Support three top-level categories: UGC NET, Joint CSIR-UGC NET, and named state/regional SET/SLET identities. One regional exam can cover multiple states/UTs; don't generate fake one-exam-per-state entries.
- Implement paginated/searchable public catalogue read endpoints with allowlisted output fields; no unpublished keys/private review records. Admin write endpoints require authentication, role guard, validation and audit logging.
- Any seed/imported public catalogue data must be clearly marked `RESEARCH_ONLY` unless officially confirmed and approved. Do not automatically label the starter's historical pattern data `PUBLISHED`.
- Add unit/integration tests for exam identity uniqueness, jurisdiction mapping, search, pagination and student/admin authorization.

### Increment 1C — Pattern versioning and approval guardrails

- Implement draft/version lifecycle and approval records with verified source URL, applicable cycle/subject, rule checksum, reviewer identity and timestamp, immutable publication snapshot and audit trail.
- Reuse `packages/exam-rules` for deterministic config validation; never introduce universal 150/180/+2/0 assumptions.
- Ensure public endpoints expose **only approved/safe rule data**; no question answers, sensitive student data or unsupported official-accuracy claims.
- Add regression tests: invalid transitions; missing proof; unauthorized approval; duplicate version; mutation after publish; historical version unchanged after newer draft; separate subject-specific rule overrides.
- Without externally checked official bulletins and authorized SME approval, leave verification/publication features unable to certify real-world exam fidelity and explicitly show `RESEARCH_ONLY`/`DRAFT` rather than `OFFICIAL_PATTERN`.
